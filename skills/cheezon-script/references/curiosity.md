# 시설보다 먼저 설명이 필요한 문제를 만든다

사용자가 확정한 채널 중심: 시설·역사·부품을 소개하는 데서 출발하지 않고, 시청자가 끝을 알고 싶어 하는 구체적인 문제를 먼저 제시한다. 신비한 건축사전의 질문 연결을 유지하고 Zem TV 표본의 대상+모순 제시, Professor Of How의 사건 재현, LifeAda의 내부 작동 설명을 활용한다. 조회수만으로 유지율이나 이 방식의 흥행 인과를 입증하지 않는다.

## 검수 전 기획
- 같은 소재의 100만 회 이상 실제 영상: 제목·채널·URL·조회수·확인일·형식(Shorts/뉴스/롱폼)·언어권을 기록한다. 관련 없는 주제의 흥행으로 대체하지 않는다. KEEP은 제작 선택이 아니다.
- 먼저 `대상 | 관찰 가능한 모순/불편/위험 | 왜 시청자에게 중요한가 | 끝에서 답할 질문 | 답을 보여줄 증거 장면`을 쓴다.
- 큰 규모·실패 가능성·숨은 사건은 근거가 있을 때만 질문으로 쓴다. '숨겨졌다'는 의도, '실패했다'는 결과를 검증 없이 만들어내지 않는다.
- 사고에서는 자연적 촉발, 취약한 설계·시공·관리, 피해를 키운 조건과 책임의 근거를 분리한다. 모든 참사를 무조건 인재나 음모로 결론내지 않는다.

## 질문을 진행시키는 법
중심 질문 → 지금 확인된 부분 답 → 그 답이 드러낸 실제 제약 → 다음 질문 → 작동 원리/증거 → 중심 질문의 답.
매 장마다 이 문구를 낭독하거나 의문문 수를 채우지 않는다. 시청자가 이미 얻은 답은 인정하고 다음 설명이 필요한 이유를 만든다.
계획표에는 `질문 ID | 시청자가 지금 아는 것 | 새 정보/제약 | 이를 보여줄 장면 | 회수 구간`을 기록한다. 질문 수·반전 비율·정답 공개 시간을 고정하지 않는다.
아무 정보도 주지 않고 '잠시 후', '충격적인 진실'로 미루지 않는다. 정답을 먼저 보여주는 편이 명확하면 보여주고 어떻게 가능한지를 추적한다.
역사·규모·기관 소개는 현재 질문의 답에 필요해지는 위치에 둔다. 해결과 무관한 연혁, 장비 목록, 반복 예고는 검수 전에 정리한다.
끝에서는 첫 장면을 다시 이해하게 만드는 원인과 작동으로 답한다. 새 범인·새 숫자·훈계를 결론에 끼워 넣지 않는다.

## 질문에서 장면으로
`원문 문장 ID | 질문 ID | 장면 기능(문제/증거/원리/결과) | 전 상태 → 변화 → 후 상태 | 고정할 구조 | 편집 오버레이 | 확인 근거`를 대본과 영상의 인계에 쓴다.
예: '압력이 낮아진다'는 문장에는 어느 공간인지와 밸브·흐름의 변화가 필요하다. 열차 외관 확대만으로 해당 원리를 설명했다고 간주하지 않는다.
전체 위치를 잡고 내부 단면을 보여준 뒤 전체 결과로 돌아온다. 그림의 화려함이나 컷 수가 아니라 질문에 필요한 정보가 실제로 보이는지 판단한다.

## 승인 경계
이 구조의 추가·재배열은 한국어 검수 전 기획에서만 한다. 검수 완료 후에는 원문 문장·내용·순서를 그대로 보존하고, 승인된 설명을 정확히 보여주는 화면을 만든다. 업그레이드라는 이유로 새 질문·위험·주장을 삽입하지 않는다.
