# Cheezon 영상 — 질문을 화면의 변화로 설명한다

프로젝트의 `D:/youtube/7. Cheezon Ki Hukumat/CHANNEL.md`와 해당 에피소드의 확정 대본·제작 기록을 먼저 읽는다. 이 스킬은 기존 영상 제작 스킬의 현재 Cheezon 진입점이다. 다른 채널의 기본값이나 과거 예시로 현재 설정을 덮지 않는다.

## 원문과 제작 단계
한국어 검수 완료본을 고정한다. 힌디어·음성·자막·장면은 같은 정보와 순서를 전달하며 길이는 실제 낭독을 따른다. 6분 상한을 적용하거나 재미를 이유로 원문을 바꾸지 않는다.
현재 요청의 승인 범위를 이어받는다. 이미지 검수 후 영상 생성 지시가 있으면 해당 검수를 거친다. 이미 승인된 작업을 다시 묻지 않으며 스킬 수정·후보 보관만으로 생성·게시를 시작하지 않는다.

## 질문을 증명하는 장면 계획
새 기획에는 [문제와 질문 연결](references/curiosity.md)을, 장면·프롬프트·편집에는 [장면 인계와 검수](references/shot-plan.md)를 읽는다.
첫 장면은 제목이 약속한 문제·모순·불편을 보여준다. 분위기용 항공샷을 먼저 늘어놓지 않는다.
실사/실사풍은 상황·규모·결과를, 단면·분해·흐름 도해는 보이지 않는 원인을 담당한다. 실사와 3D의 비율을 고정하지 않고 모든 핵심 원리가 화면에 드러나는지 확인한다.
한 장치의 부품 위치·입출구·색 의미·흐름 방향을 고정한다. 정확한 설명은 검증 가능한 모델·레이어·편집 그래픽으로 통제하며 생성 모델의 임의 변형을 원리로 채택하지 않는다.

## 생성과 카메라
이야기 장면은 밝고 자연색이 선명한 인도 현장감, 원리 장면은 밝고 구분하기 쉬운 3D/도해로 만든다. 긴장감은 낮은 노출이나 세피아가 아니라 상황·변화·결과로 만든다.
프롬프트는 장면/동작과 카메라를 분리한다: `Movement / Speed / Framing / End`. 클립당 하나의 안정된 무빙 또는 고정 카메라를 쓴다. 핵심 대상은 가운데 70%, 아래 15%는 자막 가독성을 고려한다.
원리 장면은 카메라가 고정돼도 된다. 물·밸브·힘·균열 등 설명 대상의 변화가 보여야 한다. 카메라 이동은 물리적 변화의 대체물이 아니다.
이미지→영상은 검수된 기준 그림을 활용한다. 최신 사용자가 지정한 도구를 따른다. 이 프로젝트의 최근 경로는 직접 이미지 생성과 Muse 영상 생성이며, Flow/Grok/Veo로 자동 전환하거나 계정·프로필을 섞지 않는다.
생성 플랫폼의 현재 UI·모델·비용·잔액을 확인한다. 과거 가격·한도·셀렉터는 현재 사실이 아니다. 타임아웃 후 기존 결과를 확인하고 중복 제출을 피한다.
사고·불편·오염은 설명에 필요한 범위에서 직접 보여주되, 실제 증거와 재현을 구분한다. 거절을 속여 우회하지 않고 허용되는 묘사·도해로 설계를 바꾼다. 뒤늦은 모자이크가 플랫폼 적합성을 보장하지 않는다.

## 편집과 완료
핵심 원리 문장에 그 움직임이 있는 클립을 배치한다. 관련 없는 B-roll, 같은 동작의 무의미한 재사용·역재생·루프로 길이를 채우지 않는다.
대체로 짧고 다양한 컷을 쓰되 도해를 읽을 시간과 필요한 쉼을 확보한다. 실제 낭독을 과속·삭제하지 않는다. 정밀 도해까지 강제 줌인하지 않는다.
숫자·라벨·화살표는 검증된 위치에 편집으로 넣는다. 숫자 강조는 노란 테두리, 힌디어 자막은 데바나가리 지원 폰트와 ASS Spacing 0을 쓴다.
첫·중간·끝 상태와 컷 연결을 확인한다. 대본 대응, 원리 정확성, 대상 일관성, 반복·튀는 연결, 자막·소리, 파일 전체 디코드를 검수한다. 자동 통과와 실제 장면 관찰·사람 청취를 구분한다.
최종 납품은 기본 1920×1080/30fps이며 원본 생성 해상도를 별도로 기록한다. 승인 범위에 편집·자막·캡컷·업로드 자료가 포함되면 해당 결과까지 이어간다. 게시와 썸네일 생성은 별도 실제 요청 범위를 따른다.
