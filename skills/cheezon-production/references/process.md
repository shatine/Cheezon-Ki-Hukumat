## 1. 도입부 문장 선정 → 썸네일 문구 확정
1. 대본보다 먼저 **도입부 첫 문장(중심 질문)**을 정한다.
   - 예: 7편 "버스에서 살 수 있을까요?" / "बस में रहा जा सकता है क्या?"
   - 시청자가 보는 대상의 모순·불편이 드러나는 한 문장이어야 한다.
2. **썸네일 문구 = 도입부 문장**으로 확정한다. 제목도 같은 질문을 가리킨다.
   - 확정한 뒤에는 첫 문장을 임의로 다시 쓰지 않는다.
3. 도입 30초는 강한 후킹으로 만든다.
   - "화려한 모습 → 한 달 뒤 비참한 현실" 같은 대비를 둔다.
   - 길고 자연스러운 **영상 3~5개**(각 5~10초)로 잇고, 1초짜리 몽타주는 쓰지 않는다.
   - 낡은 대상만 30초 보여 주지 않는다.

## 2. 대본 생성 → 검수 → 확정
1. 한국어 대본은 references/script-and-voice.md대로 쓰고, 근거표(주장 | 출처 URL | 상태)를 함께 만든다.
   - 출처가 없는 주장은 "미확인"으로 표시하고 사용자 결정을 받는다.
   - 7편 E0 "한 달 만에 포기"는 사용자가 유지를 선택했다.
2. 사용자가 고쳐 쓴 문장은 **그대로** 쓴다. 어색하거나 추상적인 문장은 쓰지 않는다.
3. 한국어 검수가 끝나면 **확정본 파일을 고정**한다. 그 뒤로는 내용·순서·숫자를 바꾸지 않는다.
4. 힌디어는 문장 단위로 대응해 번역하고, 줄마다 한국어 직역을 붙인다(`lines_hi_ko.tsv`).
5. 힌디어 TTS를 만든 뒤 **실측 시간표**(`narr_timing.json`)를 만든다.
   - 장면 계획은 반드시 이 실측으로 한다. 7편 v6에서는 문장 길이로 추정했다가 다시 만들었다.

## 3. 장면 계획 (문장 단위, 스크립트로 자동 점검)
- **3D 원리 설명은 반드시 움직이는 영상으로 만든다.**
  - 열·물·냉기·전기 흐름, 탱크 수위, 열교, 결로 같은 장면이 해당한다.
  - 카메라는 고정하고, 원리의 흐름만 움직인다.
- **원리가 아닌 장면은 10~20% 정도만 영상으로 만든다.** 지루함을 없애는 용도다.
  - 카메라 무빙이 들어가는 장면, 사람·차의 동작이 핵심인 장면이 대상이다.
  - 나머지는 **이미지 + 효과**로 쓴다: 느린 줌 인/아웃과 좌·중·우 이동을 번갈아 쓴다.
- **이미지 컷:** 대체로 2~4초마다 바꾼다. 4.5초를 넘기지 않는다.
  - 긴 문장은 반응·클로즈업·반전 컷을 추가 이미지로 나눈다. 7편 v9에서 31장을 추가했다.
- **영상 컷:** 10초 중 쓸 수 있는 구간을 최대한 길게 쓴다. 2~3초로 쪼개는 규칙은 폐기했다.
- **금지:** 감속(슬로모션), 마지막 프레임 정지, 같은 구간 반복·역재생, "영상 부족" 표시.
  - 7편 v5에서 한 샷을 28초 늘렸다가 크게 지적받았다.
  - 같은 소스를 다시 쓸 때는 겹치지 않는 구간만, 의도된 회수일 때만 쓴다.
- **도구:** 계획은 `tools/plan_template.py`를 새 편의 `plan\plan_v1.py`로 복사해 만든다(7편 원본: `episodes/ep07_bus/plan/plan_v9.py`).
  - 자동 점검 항목: 쓸 구간 안, 소스 겹침 없음, 이미지 재사용 없음, 원리 문장은 영상, 문장 누락 없음, 총 길이 일치.
  - 오류가 0이어야 다음 단계로 간다.
- **카메라 무빙:** 영상 클립의 약 2/10만 쓴다. 같은 방향 무빙을 연속으로 쓰지 않고, 사람 쪽으로 dolly in 하지 않는다.

## 4. 이미지 생성 → 검수 → 확정 (일관성 엄격)
1. 같은 대상(버스·밴·장소)은 **기준 그림을 반드시 첨부**한다.
   - 7편에서 Muse가 기준 그림을 거부해 글자만으로 만들었더니 버스가 달라졌고, 결국 다시 만들었다.
2. 프롬프트 첫 문장: "Using the reference image: the SAME …(형태·색·특징)".
3. 생성한 모든 장을 원본 크기로 확인하고, 필요한 곳은 확대해서 본다.

**검수 항목**

| 항목 | 기준 |
|---|---|
| 일관성 | 같은 형태·색·창 수·앞모양. **화면 속 방향**(앞이 왼쪽/오른쪽, 문 위치) |
| 의미 | 그 문장의 뜻이 한눈에 읽히는가 (예: "거절"이 거절로 보이는가) |
| 사람 | 인도 성인. 얼굴은 작게(화면 높이 약 1/4 미만), 입·코 클로즈업도 금지. 아이 없음 |
| 글자 | 생성 그림 안의 글자·숫자·번호판·상표 로고는 읽히면 탈락, 깨진 데바나가리 간판도 탈락. 흐림 처리는 최후 수단 |
| 화질 | 밝기(어두우면 탈락), 워터마크 흔적, 뭉개짐, 어색한 합성 |
| 중복 | 앞뒤 컷과 구도가 거의 같으면 탈락 (7편 n22c와 s22c) |

4. 기록은 `picks_*.md`에 남긴다: id, 기준 그림, 시도 횟수, 탈락 이유, 고른 이유.
   - 클라우드 재검수 결과도 같은 파일에 덧붙인다.
5. 이어지는 장면의 **방향**이 뒤집히면 편집에서 좌우 반전으로 맞출 수 있다(7편 o2). 단, 글자가 없는 그림일 때만.

## 5. 영상 생성 (Muse, 한 개씩)
- **프롬프트:** 장면 동작과 카메라를 나눠 쓴다(Movement / Speed / Framing / End). 기본은 `locked-off static shot`.
  - "One single continuous camera movement…" 문구는 금지(전 클립이 돌아 멀미가 났다).
- **생성 후 1초 간격 프레임 확인:**
  - 밝기 변화: 0.5초마다 평균 밝기를 측정한다.
  - 카메라가 갑자기 밀고 들어가 얼굴이 커지지 않는가.
  - 모양이 변하지 않는가.
  - 원리 방향이 맞는가.
  - 글자가 나타나지 않는가.
- **쓸 구간:** 실측해서 기록하고 계획의 USE에 넣는다.
  - 7편 PB는 끝 3초가 어두워져서 편집에서 밝기를 보정했다.
  - 7편 o1은 0~5.4초만 썼다.
- **영상 길이:** 10초를 가정하지 말고 현재 도구 설정을 확인한다.
